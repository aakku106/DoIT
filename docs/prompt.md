# DoIT — Project Brief (for AI)

Go CLI todo app. SQLite via `ncruces/go-sqlite3` (WASM). Typed query layer generated by `sqlc`.

## Stack
- Go 1.25+, SQLite (WAL), `sqlc` codegen.
- Entrypoint: `cmd/todo/main.go`. Handlers: `internal/cli/commands.go`. Store: `internal/store/` (generated). DB: `internal/db/sqlite.go`.

## Data
Four tables — `todos`, `completed`, `trash`, `ignored`. Each: `id INTEGER PRIMARY KEY`, `session TEXT` (hardcoded `"todo"`), `title TEXT`, timestamp columns. Schema truth: `sql/schema.sql` (embedded via `//go:embed`). Queries truth: `sql/queries.sql`. Migrations dir is stale — do not use.

## Key rules (agents must know)
1. **CLI IDs are display indices** (0-based, per `ls` output), NEVER DB row ids. Handlers map them through `ListTodoIDs`/`ListCompletedIDs`/`ListTrashIDs`/`ListIgnoredIDs`.
2. **Never hand-edit `internal/store/`** — generated. Edit `sql/*.sql` then `sqlc generate`.
3. **DB discovery walks upward** from cwd looking for `.doit/`. Must run `doit init` first; database is `.doit/doit.db`.
4. Session is **hardcoded** `"todo"` everywhere; multi-session stubbed via `sessionCall(args)` (empty).

## Commands
- `init` — create `.doit/` + DB.
- `add|a <task>` (`add` requires exactly one arg).
- `list|ls`, `done|d <id>`, `remove|rm <id>`.
- `completed|c [list|remove|nuke]`, `trash|t [...]`, `ignored|i [...]`.
- `move|mv <t|c|i> <id> <t|c|i>` — move between trash/completed/ignored.
- Anything else → `sessionCall` placeholder.

## Build / Run
```bash
go build -o doit ./cmd/todo
go run ./cmd/todo add "task"
./dev-build.sh   # dev build to ~/go/bin/xdoit
```
